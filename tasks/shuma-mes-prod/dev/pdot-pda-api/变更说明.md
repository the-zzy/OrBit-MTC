日期：2026-11-17  
规范：`dev-api-interface` v2.1.0（HTTP 入 MES，采用 BP + WG 两件交付）

## 0. V2.2 资产查询与页面流程调整

- `PDOTInitQuery` 新增 `queryType=assets` 和 `@AssetsJson`；`assets` 统一支持 1～100 条查询，不另设单资产动作。
- 每条查询结果增加 `assetLotSN/success/message`，未匹配不影响其他条目；查询只读，不写盘点数据。
- PDA 扫条码或结束 RFID 识别时只调用 `assets` 查询并填充网格；点击“盘点”后将整个网格交给 `batchCheck`，按 `resultsJson` 逐条更新状态。
- 设备码归一统一为四步：资产编号 → `EquipmentNumber` → 去前导 0 → 「公司码 + 资产编号」。数码正式库现有资产 `EquipmentNumber` 全部为空，设备码 `10103001185` 通过第四步匹配到 `3001185`。
- 总装测试库已按上述映射造三条联调数据（`3001185/3001337/3001349`），脚本见 `PDOT_TestData_总装资产.sql`。
- 本次仅修改本地 SQL、文档、App 和 BP/WG 交付件，未执行数据库更新、未导入或发布平台；V2.2 尚需重新部署并联调。

## 1. 本次变更

- 新增网关入口过程 `dbo.APIBP_PDOTInitQuery`、`dbo.APIBP_PDOTOperate`。
- 原 `/pda/pdot/*` 地址改为 `/thirdparty/mes/PDOTInitQuery`、`/thirdparty/mes/PDOTOperate`。
- 返回包装由 `success/code/message/data` 改为 `state/errcode/msg/data/transactionId`。
- 两个过程均固定返回一行；集合数据通过 JSON 字符串字段返回，避免多结果集无法映射到网关出参。
- `PDOTOperate` 的 `assets` 按 `Array + children` 定义，经 `${$.http.assets}` 传给 `@AssetsJson`，再由 SQL Server 2016 `OPENJSON` 解析。
- 未新增物理业务表；未在数据库执行 SQL，未在平台导入或发布。

## 3. 人工部署顺序

1. 在确认后的 SQL Server 环境人工执行 `APIBP_PDOT_Gateway.sql`；可用 `APIBP_PDOT_Gateway_TestCase.sql` 做后续人工验证。
2. 在 ESB 编排导入两份 `BP_*.bson`。
3. 导入前人工在 ESB「指定数据源」核对数据源。本次两份 BP 的 `dbConnId` 均已写为 **000037（总装 MES 测试环境）**；部署到数码正式环境前需重新确认并替换为对应数据源。
4. 在 API 列表/网关导入两份 `WG_*.bson`；其 `backendUrl` 分别指向上一步的内部地址。
5. 按 `README.md` 的成功、业务失败和批量部分失败样例做联调。

AI 仅生成交付文件，不代替人工执行 SQL 或导入平台。

## 4. 调用方修正点

- 先判断 `state` / `errcode`，再取 `data[0]`。
- 业务结果看 `data[0].returnValue`，消息看 `data[0].returnMessage`。
- `plansJson/pdTypesJson/departmentsJson/listJson/resultsJson` 必须再次 JSON.parse；空集合是 `"[]"`。
- 单条盘点从 `description/roomer/unUsedNum` 取值；批量逐条结果从 `resultsJson` 取值。
- `location` 查询不再传 `OrBitUserId`，也不要求 `stocktakeId`。
- 批量接口整体处理完成时 `returnValue=0`，即使部分资产失败；应逐项检查 `success`。
